## What SETU is

Post-discharge patient monitoring for rural India — a hackathon project (started 2026-09-03). Patients get automated phone check-ins; AI extracts symptoms from speech, a **deterministic rule engine** (not the AI) decides risk level (normal/warning/critical), and critical cases alert an ASHA worker (village health worker) and the hospital. Core principle: **"AI extracts. Rules decide. Humans act."** — the LLM never makes the risk decision, only converts speech/text into structured data.

Three user roles, strictly separated at the backend query level (not just UI):
- **Patient** — receives calls, has a simple mobile-web app (check-in, reminders, AI chat, profile)
- **ASHA worker** — sees only their assigned patients, field app with map
- **Hospital/Admin** — sees all patients in their hospital, dashboards, analytics, reports

Stack: FastAPI (Python) + PostgreSQL backend, React + Vite + TypeScript + Tailwind frontend. Full architecture/rules/philosophy is in `SETU_PROJECT_CONTEXT.md` on the user's Downloads (not in this repo) — treat it as background, not gospel; a lot has changed since.

**IMPORTANT gotcha, confirmed again this session:** the backend process keeps dying/getting orphaned in this environment. `taskkill //F //PID <pid>` on the PID `netstat` reports as LISTENING often reports "SUCCESS" while the port keeps serving stale code — the process is invisible to PowerShell's `Get-Process` (different PID namespace/visibility in this sandbox). **Reliable fix:** use PowerShell, not taskkill: `Get-CimInstance Win32_Process -Filter "name='python.exe'"` to see real command lines and PIDs, then `Stop-Process -Id <id1>,<id2>,... -Force`. ## Prescription scan/upload/analyze feature — completed and verified live

User asked "a doc or patient can scan and upload a prescription image and that will be stored and analysed — what are we using here?" first as a question, then asked to build it. 1. **Document storage filename collision** (`backend/app/modules/documents/router.py`): uploads were saved as `uploads/{original_filename}` with no uniqueness — two different patients uploading a file both named e.g. "prescription.jpg" would silently overwrite each other on disk (the DB rows would stay separate with mismatched checksums pointing at the wrong bytes). 3. **`get_patient_prescriptions` crashed with `MissingGreenlet`** (`backend/app/modules/prescriptions/service.py`): accessed `p.medications` (a lazy SQLAlchemy relationship) without eager-loading, which isn't supported under async SQLAlchemy — would 500 the instant any prescription with medications existed (i.e. always, in practice).
